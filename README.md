## 1. 지금까지 한 작업 (2026-10-06 ~ 10-10)

### 접근 방향 (팀 합의)
- 탐지는 **로컬 규칙 + 오픈소스 모델** 기반으로 하고, AI API는 로컬로 판단하기 애매한 경우에만 최소한으로 씁니다(키는 `.env`로 분리).
- 오탐은 정확도(35점)를 깎지만 **검출 개수 배점(45점)이 더 크니** 임계값을 너무 보수적으로 잡지 않습니다.

### 탐지 파이프라인
```
진입 URL ─▶ Playwright 크롤링 ─▶ extract.js (숨김 요소·텍스트 추출)
        ─▶ textnorm (닮은꼴 복원·자모 재조합)
        ─▶ adscore 룰 점수
              ├─ 높음  → 불법광고
              ├─ 낮음  → 정상
              └─ 경계(1.5~4) → Laya 분류기로 2차 판정
        ─▶ result.json (제출 형식) + report.json (판정 근거)
```

### 오픈소스 모델 비교
- **Laya-multilingual 채택**: CPU에서 돌아가고 한국어도 지원합니다.
- **OpenJev 제외**: GPU가 필수라서 평가 PC 조건에 맞지 않습니다.
- Laya를 템플릿 학습 데이터로 파인튜닝했습니다(`training/`). 2026-10-12에 학습 데이터를 다시 만들었습니다(아래 참고).

### 프로토타입 성능
| 구성 | 모의 사이트 (정답 23건) | 손으로 쓴 검증셋 (60문장) | dev (처음 보는 어휘, 300문장) |
|---|---|---|---|
| 룰만 | – | 정확도 0.650 / 재현율 0.30 | 정확도 0.700 |
| Laya 제로샷 | – | 정확도 0.783 (오탐 12) | 정확도 0.700 (오탐 86) |
| Laya 파인튜닝 v1 (900문장) | – | 정확도 0.833 | – |
| **Laya 파인튜닝 v2 (1600문장)** | – | **정확도 0.950 (오탐 1)** | **정확도 0.940** |
| **룰 + Laya v2(경계만)** | **정밀도 1.0 / 재현율 1.0 (10.5초)** | 정확도 0.767 / 정밀도 1.0 | 정확도 0.870 / 정밀도 0.991 |

**학습 데이터 v2에서 바꾼 점** (`training/make_dataset.py`)
- v1은 겉모양으로 정답을 맞힐 수 있었습니다. 예를 들어 영문은 광고 65%·정상 0%, `[공지]`·날짜는 정상에만 있었습니다.
  v2는 영문·숫자·도메인·@아이디·전화번호가 정상 쪽(Copyright, `.go.kr`, 대표전화, 공식 인스타그램 등)에도 나오게 했습니다.
  말머리·장식·띄어 쓴 글자는 양쪽에 같은 확률로 붙이고, 길이 분포도 맞췄습니다.
- 광고 키워드가 들어간 공공 문구(놀이터 보수, 성인반, 도서 대출, 상품권 할인, 체육진흥투표권, 마약 예방 교육 등) 약 100종을 넣었습니다.
- 광고 어휘를 늘렸습니다: 대출깡·현금화, 위조, 외국어(영어·인도네시아어·중국어·일본어) 스팸.
- 어휘마다 20%를 떼어 `dev.jsonl`에만 넣습니다. 학습에 없던 키워드로 일반화 성능을 봅니다.
- 생성할 때 특징 비율, 규칙 점수 구간 분포, 검증셋·모의 사이트와 8글자 이상 겹치는 문장(현재 0건)을 출력합니다.
- `--label-smoothing 0.1`로 학습하면 loss가 0이 되지 않고 0.20 근처에 머뭅니다. dev 기준 ECE는 0.231 → 0.054로 떨어졌습니다.

⚠️ **수치는 여전히 낙관적입니다.** 모의 사이트, 정답, 룰, 학습 데이터, 검증셋을 모두 한 사람이 만들었습니다.
v2는 검증셋과 문장을 공유하지 않지만, 대출깡·외국어 스팸 같은 범주는 겹칩니다.
- **룰 + Laya의 재현율은 Laya가 아니라 룰에서 막힙니다.** 검증셋 광고 30건 중 14건은 룰 점수가 1.5 이하라 Laya에 넘어가지도 않습니다.
  Laya 단독은 0.950인데 파이프라인은 0.767인 이유입니다.
- v2 모델은 `토토 환전 빠른 곳 …`을 정상(p=0.09)으로 봅니다. 합법 토토 관련 정상 문구를 넣으면서 생긴 과보정으로 보입니다.
  이 문장은 룰 점수가 높아 파이프라인 결과에는 영향이 없습니다.

### 개발하면서 찾은 함정 (같은 실수 반복 금지)
- **NFKC 정규화가 호환자모(ㅅ)를 조합자모(ᄉ)로 바꿉니다.** 그래서 자모 재조합을 NFKC보다 **먼저** 하고, 호환자모 범위는 NFKC에서 제외합니다.
- **iframe 안의 `<a href="#">` 때문에 위젯 문서가 단독 페이지로 크롤링되면서 같은 오탐이 중복으로 나옵니다.** 그래서 iframe 문서 URL은 크롤링에서 제외합니다.
- **요강은 iframe `src`를 절대주소로 쓰라고 하지만 HTML 속 값은 상대경로입니다.** 그래서 채점기는 CSS 선택자 문자열이 아니라 브라우저가 해석한 `el.src`로 비교합니다.

파인튜닝한 모델(`models/laya-illegal-ad/model.safetensors`)은 **614MB**라서
GitHub의 **파일당 100MB 제한**을 넘어 저장소에 올릴 수 없습니다.
**각자 `pip install laya`로 설치한 뒤** 아래 중 하나로 쓰세요.

### 방법 A. 기본 모델 바로 쓰기 (제로샷, 가장 간단)
`pip install laya`를 하면 처음 실행할 때 HuggingFace에서 기본 모델을 자동으로 받습니다(인터넷 필요, 수백 MB).
```bash
.venv/bin/python -m detector.main http://127.0.0.1:8765/ --out runs/full \
    --model convaiinnovations/laya-multilingual
```

### 방법 B. 직접 파인튜닝해서 만들기
프로토타입과 같은 설정입니다. CPU로도 돌아가지만 시간이 걸립니다.
```bash
# 1) 학습 데이터 생성 (train.jsonl·dev.jsonl, 이미 들어 있으니 수정했을 때만 실행)
#    실행하면 광고/정상별 특징 비율, 규칙 점수 구간 분포, 검증셋·모의 사이트와 겹치는 문장을 출력합니다.
.venv/bin/python training/make_dataset.py

# 2) 파인튜닝 → models/laya-illegal-ad/
.venv/bin/laya-train --data training/train.jsonl --eval-data training/dev.jsonl \
    --base convaiinnovations/laya-multilingual \
    --out models/laya-illegal-ad \
    --epochs 3 --micro-batch 16 --grad-accum 2 --loss soft-ce --label-smoothing 0.1 --seed 0
```
`models/laya-illegal-ad`가 있으면 탐지기가 `--model` 옵션 없이 자동으로 씁니다.

### 방법 C. 모델 없이 룰만 쓰기
```bash
.venv/bin/python -m detector.main http://127.0.0.1:8765/ --out runs/rules --no-ml
```
경계 구간은 정상으로 처리합니다(재현율이 떨어짐).

## 5. 실행 방법

### 화면으로 실행 (기본)
```bash
.venv/bin/python testsite/server.py     # (테스트할 때) 모의 사이트 → http://127.0.0.1:8765/
.venv/bin/python -m ui.server           # 화면 → 브라우저가 자동으로 열림 (http://127.0.0.1:8780/)
```
Windows에서는 `run_ui.bat`을 실행합니다.

1. URL을 입력하고 **탐지 시작**을 누르면 진행률(수집한 페이지 수, 현재 URL)이 표시됩니다.
2. 끝나면 **대시보드**가 나옵니다.
   - **광고 청정도 게이지:** 처리할 불법광고가 남지 않은 페이지 비율입니다. 등급은 처리 필요 건수 기준으로 청정(0건), 양호(1~3건), 주의(4~10건), 오염(11건 이상) 네 단계입니다.
   - **통계 카드:** 탐지된 불법광고, 처리 필요, 점검 페이지(소요 시간), 청정 등급
   - **오염원 분석:** 은닉 기법별 건수입니다. 누르면 그 기법만 걸러 볼 수 있습니다.
   - **탐지 로그:** 처리가 필요한 항목부터 보여 주고, 누르면 결과 표의 상세 근거로 이동합니다.
3. 행을 누르면 **판정 근거**를 볼 수 있습니다: 위치(CSS 선택자), 은닉 방식, 원문과 복원 문구, 걸린 키워드, 점수, 규칙/AI 중 무엇이 판정했는지.
4. 항목마다 **검토 상태**(미검토, 불법광고 확인, 오탐, 조치 완료)와 **메모**를 저장하고, 기법·상태·검색어로 걸러 볼 수 있습니다. 조치 완료나 오탐으로 처리하면 청정도가 올라갑니다. **엑셀(CSV) 내보내기**도 됩니다.
5. 왼쪽 **점검 이력**에서 지난 점검 결과를 다시 열 수 있습니다(`history/<실행시각>/`). 카드의 휴지통 버튼으로 하나씩, **전체 삭제**로 한꺼번에 지울 수 있고, 지우기 전에 화면 안에서 한 번 더 확인합니다. 지워지는 것은 `history/` 안의 이력뿐이고, 실행 폴더의 제출용 `result.json`은 그대로 남습니다.
6. **내보내기는 두 가지입니다.**
   - **result.json 다운로드:** 요강 붙임4 형식의 제출용 파일입니다. 탐지 엔진이 저장한 파일을 그대로 내려받습니다.
   - **엑셀(CSV) 내보내기:** 검토·조치 관리용입니다. 앞 6열(`id`, `url`, `is_violation`, `location`, `evidence_text`, `technique`)은 result.json findings와 같은 이름·순서·값이고, 그 뒤에 복원 문구, 판정 근거, 검토 상태, 메모를 붙입니다.

`result.json`과 `report.json`은 요강대로 **구동 폴더**에 생성됩니다. 개발할 때는 프로젝트 루트, exe로 묶으면 exe가 있는 폴더입니다.

**result.json 형식**은 요강 붙임4 스키마를 그대로 따릅니다. 최상위는 `meta`와 `findings`뿐이고, BOM 없는 UTF-8로 저장하며, 0건이어도 `findings: []`를 넣습니다. `eval/validate_result.py`로 검증할 수 있습니다.

**접속 실패 처리**
- 진입 페이지에 접속하지 못하면 화면에 "확인 불가"와 경고가 뜨고, 명령줄 실행은 종료 코드 2로 끝납니다. 0건을 '청정'으로 오판하지 않기 위해서입니다.
- 일부 페이지만 실패하면 그 목록을 경고로 보여 줍니다.
- 실패 정보는 `report.json`의 `entry_failed`, `failed_pages`, `http_errors`에만 기록하고, `result.json` 스키마는 바꾸지 않습니다.

- 화면은 내 PC 안에서만 열리는 로컬 서버(`127.0.0.1`)입니다. 외부 서버에 올리지 않습니다.
- `result.json`은 탐지할 때마다 덮어쓰고, 지난 결과는 `history/`에 남습니다. 이력을 지우려면 `history/` 폴더를 삭제하세요.
- 정상 판정 후보도 보기를 켜면 탐지기가 걸러낸 후보(예: 접근성용 "본문 바로가기")까지 흐리게 표시됩니다.
- "최대 페이지"를 비워 두면 시간 한도(약 19분) 안에서 사이트 전체를 탐색합니다. 실제 사이트를 빠르게 훑어보고 싶을 때만 20 정도로 줄여 보세요.

### 명령줄로 실행

터미널 두 개를 씁니다.

```bash
# 터미널 1 — 모의 사이트 띄우기
.venv/bin/python testsite/server.py            # → http://127.0.0.1:8765/

# 터미널 2 — 탐지 (모델 옵션은 4장 참고)
.venv/bin/python -m detector.main http://127.0.0.1:8765/ --out runs/full

# 채점 (testsite/ground_truth.json 기준)
```

### 탐지기 옵션
| 옵션 | 기본값 | 설명 |
|---|---|---|
| `<진입URL>` | (필수) | 크롤링을 시작할 주소 |
| `--out` | 구동 폴더 (프로젝트 루트 / exe 폴더) | `result.json`, `report.json` 저장 위치 |
| `--max-pages` | 0 (제한 없음) | 방문할 최대 페이지 수. 0이면 시간 예산 안에서 전부 탐색 |
| `--time-budget` | 1620 (27분) | 전체 목표 시간(초). 적격평가 상한 30분에서 3분 여유 |
| `--llm-reserve` | 360 (6분) | 나중에 붙일 LLM 최종 검증 몫으로 남겨 두는 시간(초). 크롤링은 `time-budget − llm-reserve − 판정 2분`까지 |
| `--concurrency` | 4 | 동시에 여는 탭 수 |
| `--timeout` | 15000 | 페이지 로딩 제한 시간(ms) |
| `--model` | `models/laya-illegal-ad` | Laya 모델 경로 또는 HuggingFace ID |
| `--no-ml` | – | Laya 없이 룰만 사용 |
| `--user-agent` | 일반 Chrome | 크롤러 User-Agent. 기본으로 평범한 한국어 브라우저처럼 접속합니다(로캘 `ko-KR`, `Accept-Language` 포함). 점검 기관에 신원을 밝혀야 하면 뒤에 도구명을 덧붙이세요. |
| `--no-extra` | – | 게시형(은닉 없는) 불법광고 탐지를 끄고 적격평가 4종만 탐지 |

> **크롤링 순서와 시간 예산.** 페이지 수로 자르지 않고, 시간 예산 안에서 아래 순서로 **전부** 탐색합니다(`detector/frontier.py`).
> 1. 진입 페이지 주변(메뉴) → 2. 누구나 글을 쓰는 게시판·목록 페이지(Q&A, 자유게시판, 후기 등) → 3. 목록에서 제목이 수상한 글 → 4. 나머지 글·일반 페이지
> - 숨김 광고(적격평가 4종)는 제목이 멀쩡한 글 본문에도 있을 수 있어서, 우선순위만 낮출 뿐 버리지 않습니다.
> - 수상한 제목이 3개 이상 걸린 목록(스팸이 쌓인 게시판)에서 나온 다음 쪽 목록은 크게 앞당깁니다. 목록 한 쪽에 스팸 제목이 20여 개씩 보이기 때문입니다.
> - 같은 글·목록이 여러 주소로 열리는 경우(목록 위치·검색 상태 매개변수, 카페24의 `/board/이름/번호/`와 `list.html?board_no=`)는 한 번만 봅니다.
> - 광고가 있을 수 없는 기능 페이지(글쓰기·수정·삭제·로그인·다운로드 등)는 열지 않습니다. 카페24 글쓰기 페이지는 봇 확인 화면으로 넘어가 시간만 씁니다.
> - 버리는 것은 검색·정렬·달력처럼 같은 형태가 끝없이 생기는 주소뿐입니다(형태당 20개).
> - 게시판 하나가 시간을 독점하지 않도록 게시판끼리 번갈아 봅니다.
> - 시간 한도에 닿으면 새 페이지는 열지 않고 그때까지 찾은 결과로 `result.json`을 저장합니다(`report.json`의 `stopped_by_time`, `left_in_queue`).

> **게시형 불법광고 탐지(추가 유형).** 요강은 "게시·은닉된 불법광고"를 대상으로 하고, 4종(닮은꼴·자모·투명·화면 밖)은 적격평가 기준이며 본심사에서는 추가 유형도 평가합니다.
> 그래서 숨기지 않고 **그대로 게시된** 불법광고(예: 게시판 제목 `✅구글검색 벳모아티비✅ 무료중계`, `비상금대출`)도 탐지합니다(`technique=POSTED`).
> - 적격평가 4종은 `result.json`에 그대로 두고, 게시형은 **`result_extra.json`**(technique=`ETC`, `extra_finding`에 유형명)으로 분리합니다. 적격평가 제출물은 영향받지 않습니다.
> - '보인다'는 것 자체는 단서가 아니므로, 룰 점수가 정상 확정선을 넘는 텍스트만 후보로 올려 오탐·후보 폭증을 막습니다. 공익 안내(`불법 도박 신고 1336` 등)는 감점 규칙으로 제외합니다.

> **접속이 막히는 사이트에 대하여.** 끝 슬래시가 없어 내부 주소로 잘못 리다이렉트되는 경우(`/path` → 접속 불가)는 자동으로 `/path/`를 다시 시도합니다.
> 반면 일부 공공 사이트(예: 정부24)는 자동 접속 자체를 차단합니다(스크립트 기반 단말 차단). 이때는 User-Agent를 바꿔도 뚫리지 않으며, 이는 기관이 의도한 접근 통제이므로 우회하지 않습니다.
> 실제 기관 사이트를 점검하려면 해당 기관에 점검 IP·User-Agent 허용을 요청하는 것이 정상 절차입니다.
