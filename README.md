## 1. 지금까지 한 작업 (2026-10-06 \~ 10-15)

### 접근 방향 (팀 합의)
- 탐지는 **로컬 규칙 + 오픈소스 모델** 기반으로 하고, AI API는 로컬로 판단하기 애매한 경우에만 최소한으로 씁니다(키는 `.env`로 분리).
- 오탐은 정확도(35점)를 깎지만 **검출 개수 배점(45점)이 더 크니** 임계값을 너무 보수적으로 잡지 않습니다.

### 탐지 파이프라인
```
진입 URL ─▶ Playwright 크롤링 (다른 사이트로의 이동은 취소 — 기생 페이지 대응)
        ─▶ extract.js (숨김 요소·텍스트·링크 주소·제목/메타 추출)
        ─▶ textnorm (닮은꼴 복원·자모 재조합·숫자 위장 복원)
        ─▶ adscore 룰 점수 + 문맥 가산·감점 (본문 삽입 링크, 기생 페이지, 페이지 제목의 경고·보도 맥락)
              ├─ 4점 이상  → 불법광고 (규칙)
              ├─ 1.5점 이하 → 정상 (규칙)
              └─ 그 사이    → jev(Laya 분류기)로 2차 판정
        ─▶ 중복 합치기 (같은 주소·내용·줄)
        ─▶ result.json (제출 형식) + report.json (항목별 점수·판정 근거)
```

### 오픈소스 모델 비교
- **Laya-multilingual 채택**: CPU에서 돌아가고 한국어도 지원합니다.
- **OpenJev(현재 이름 SemIf) 제외**: Jev(TypeSafe의 비공개 판정 모델)의 *질문 방식*만 따라 한 프로젝트로, 실제 판정은 Qwen 같은 일반 LLM(4B 이상)이 합니다. CPU로도 돌릴 수는 있지만 후보 수천 개를 30분 안에 판정하기엔 너무 느리고, 파인튜닝 기능이 없습니다.
- 참고로 Laya는 Jev와 API 형식이 같은 오픈 모델(Apache-2.0)입니다. 팀 안에서 "jev"라고 부르는 것은 이 Laya 파인튜닝 모델입니다.
- Laya를 템플릿 학습 데이터로 파인튜닝했습니다(`training/`). 2026-10-12에 학습 데이터를 다시 만들었습니다(아래 참고).

**학습 데이터 v2에서 바꾼 점** (`training/make_dataset.py`)
- v1은 겉모양으로 정답을 맞힐 수 있었습니다. 예를 들어 영문은 광고 65%·정상 0%, `[공지]`·날짜는 정상에만 있었습니다.
  v2는 영문·숫자·도메인·@아이디·전화번호가 정상 쪽(Copyright, `.go.kr`, 대표전화, 공식 인스타그램 등)에도 나오게 했습니다.
  말머리·장식·띄어 쓴 글자는 양쪽에 같은 확률로 붙이고, 길이 분포도 맞췄습니다.
- 광고 키워드가 들어간 공공 문구(놀이터 보수, 성인반, 도서 대출, 상품권 할인, 체육진흥투표권, 마약 예방 교육 등) 약 100종을 넣었습니다.
- 광고 어휘를 늘렸습니다: 대출깡·현금화, 위조, 외국어(영어·인도네시아어·중국어·일본어) 스팸.
- 어휘마다 20%를 떼어 `dev.jsonl`에만 넣습니다. 학습에 없던 키워드로 일반화 성능을 봅니다.
- 생성할 때 특징 비율, 규칙 점수 구간 분포, 검증셋·모의 사이트와 8글자 이상 겹치는 문장(현재 0건)을 출력합니다.
- `--label-smoothing 0.1`로 학습하면 loss가 0이 되지 않고 0.20 근처에 머뭅니다. dev 기준 ECE는 0.231 → 0.054로 떨어졌습니다.

⚠️ **수치는 여전히 낙관적입니다.** 모의 사이트, 정답, 룰, 학습 데이터, 검증셋을 모두 한 사람이 만들었습니다.
v2는 검증셋과 문장을 공유하지 않지만, 대출깡·외국어 스팸 같은 범주는 겹칩니다.
- **룰 + Laya의 재현율은 Laya가 아니라 룰에서 막힙니다.** 검증셋 광고 30건 중 14건은 룰 점수가 1.5 이하라 Laya에 넘어가지도 않습니다.
  Laya 단독은 0.950인데 파이프라인은 0.767인 이유입니다.
- v2 모델은 `토토 환전 빠른 곳 …`을 정상(p=0.09)으로 봅니다. 합법 토토 관련 정상 문구를 넣으면서 생긴 과보정으로 보입니다.
  이 문장은 룰 점수가 높아 파이프라인 결과에는 영향이 없습니다.

### 2026-10-14 \~ 10-15: 실사이트 데이터로 규칙·크롤러 고도화

모의 사이트가 아니라 **실제 스팸이 있는 공공·단체 사이트**를 기준으로 고쳤습니다.

**평가 데이터**
- **라벨 데이터 4,863문구:** 점검 이력 13건과 팀원이 찾은 URL 27개에서 나온 문구, 새로 크롤링한 14개 사이트의 탐지 문구 표본입니다. 문구마다 광고/정상/애매를 붙였습니다(규칙 점수를 보지 않고 문구만 보고 판단).
- **외부 시험 사이트 89페이지:** 검색으로 찾은 스팸 게시 공공 페이지 51개(28개 기관)와, 불법광고를 *다루는* 정상 페이지 38개(가짜 비아그라 적발 보도, 작업대출 주의보, 도박 예방교육 등)입니다.
  삭제된 글 3개와 사이트가 스크립트로 숨긴 글 2개는 시험에서 뺐습니다.

**규칙 (`detector/adscore.py`, `textnorm.py`)**
- **키워드군 추가:** 출장 마사지·성매매 은어(홈타이·토닥이·출장샵·휴게텔·콜걸·텐프로 등), 불법 의약품(비아그라·시알리스·카마그라·성인약국·구충제 직구), 검색 상위노출 도배(찌라시·상위노출), 대포계좌(대여계좌·계좌매입·대포통장), 카드깡, 게임 핵 판매, 불법 웹툰·영상(뉴토끼·누누티비·평생주소), 060 유료 전화
- **오탐 수정:** `bet`이 `Better`에, 이메일·`@media`가 메신저 아이디로, `오피`가 `오피니언`에 걸리던 문제를 고쳤습니다. 숨김 블록 안의 CSS·JS 코드는 채점하지 않습니다.
- **단어 경계 인식:** 띄어쓰기를 지우고 비교하면 `분야 설계 → 야설`, `구성: 인력 → 성인`, `2026년도 배움터 → 도배`, `19.(금) → 19금`처럼 단어를 넘는 가짜 일치가 생깁니다. 두 글자 키워드는 단어 경계를 넘지 못하게 했습니다. `토 토`, `바.카.라`처럼 한 글자씩 띄운 우회는 계속 잡습니다.
- **숫자 위장 복원:** `l9금`, `O6O-5OO-266O`, `ㅇIㅇ-5309`를 숫자로 되돌려 판정하고, 위장 흔적에도 가산점을 줍니다.
- **감점 맥락:** 실태 보도·채용·경고 글(`학생·의원·집계·채용·주의보·적발·검출·보도자료` 등). `도박`은 스팸이 쓰지 않는 말이라(라벨 데이터 광고 0 / 정상 57) 감점으로 옮겼습니다.
- **가중치 근거:** 라벨 데이터에서 근거별로 광고/정상 등장 횟수를 세어 바꿨습니다(예: `domain` 광고 65 / 정상 1 → 1.5점, `%` 광고 44 / 정상 126 → 0.5점).
  로지스틱 회귀로 가중치를 통째로 다시 맞춰 봤지만, **사이트 단위 교차검증**에서 처음 보는 사이트의 광고를 더 많이 놓쳐(6.8% → 12.8%) 채택하지 않았습니다. 하한 1.5는 데이터로 계산해도 1.5가 나왔습니다.

**판정·크롤링 (`detector/main.py`, `extract.js`)**
- **본문 삽입 링크(`link-farm`):** 정상 글 문장 사이에 같은 외부 사이트로 가는 링크를 3개 이상 끼우고 링크 글자만 `출장마사지·홈타이`로 바꾸는 스팸에 가산점을 줍니다.
- **페이지 맥락(`page-context`):** 문서 제목과 본문 제목 요소(h1\~h3, class에 `tit`·`subject`)가 경고·보도 글이면 그 페이지의 게시형 후보를 최대 4점 깎습니다. 숨김형 광고는 깎지 않습니다.
- **기생 페이지:** 공공 서버에 심어진 페이지가 스크립트로 성인·도박 사이트로 넘기는 경우, 다른 사이트로의 이동을 204 응답으로 취소합니다. 그러면 원래 페이지에 머물러 검사하고, 크롤러가 광고 사이트에 접속하지 않습니다. 이동 시도 자체도 가산점(`external-redirect`)을 줍니다.
- **제목·메타 태그:** 본문이 거의 없거나, 외부로 넘기려 하거나, 제목만 광고로 바꿔치기된 페이지에서는 `<title>`, `meta description/keywords`, `og:title`도 검사합니다.
- **중복 합치기:** 아래 「중복 탐지 합치기」를 참고하세요.
- **시작 페이지 45초:** 첫 응답에만 8\~10초 걸리는 사이트가 있어, 시작 페이지는 접속 제한 시간을 45초로 늘렸습니다. 시작 페이지를 못 열면 점검 전체가 0건이 되기 때문입니다.
- **항목별 점수(`score_detail`):** `출장마사지 +3, link-farm +3, 학생 −1.5`처럼 근거별 점수를 `report.json`·화면·CSV에 남깁니다. 나중에 LLM 검증 단계의 입력으로 그대로 씁니다.

| 같은 줄 중복 남은 것 | 0건 (14개 사이트 모두) |
| 규칙 확정 정밀도 | 1,820 / 1,822 (99.9%) |
| jev 판정 정밀도 | 761 / 767 (99.2%) |

**새 시험 사이트 68페이지** (처음 보는 기관 40여 곳, 규칙을 고치기 전에 한 번만 측정)

| 구성 | 스팸 페이지 탐지 (48) | 정상 페이지 오탐 (20) |
|---|---|---|
| 규칙만 | 43 | 5 |
| 규칙 + jev v1 (현재 기본) | 47 | 10 |
| 규칙 + jev v3 | 47 | 7 |

- 놓친 1개는 브라우저 화면에서는 글이 비공개라 보이지 않고, 원본 HTML의 `<title>`에만 광고가 있는 글입니다.
- 정상 페이지 오탐은 모두 불법광고를 *다루는* 공식 글입니다(범정부 도박 대응 보도자료, 생활법령, 경찰청 신고 FAQ, 누누티비 운영자 구속 기사, 가짜 비아그라 경고, 카지노 딜러 직업 소개). 규칙만으로는 한계가 있어 LLM 검증 단계가 필요한 근거입니다.

### 개발하면서 찾은 함정 (같은 실수 반복 금지)
- **NFKC 정규화가 호환자모(ㅅ)를 조합자모(ᄉ)로 바꿉니다.** 그래서 자모 재조합을 NFKC보다 **먼저** 하고, 호환자모 범위는 NFKC에서 제외합니다.
- **iframe 안의 `<a href="#">` 때문에 위젯 문서가 단독 페이지로 크롤링되면서 같은 오탐이 중복으로 나옵니다.** 그래서 iframe 문서 URL은 크롤링에서 제외합니다.
- **요강은 iframe `src`를 절대주소로 쓰라고 하지만 HTML 속 값은 상대경로입니다.** 그래서 채점기는 CSS 선택자 문자열이 아니라 브라우저가 해석한 `el.src`로 비교합니다.
- **다른 사이트로의 이동을 `route.abort()`로 막으면 크롬이 오류 화면(`chrome-error://`)으로 바꿔 원래 문서가 사라집니다.** 그래서 204(내용 없음)로 응답해 이동만 취소합니다.
- **삭제된 게시글도 `<title>`·`og:title`에는 원래 제목이 남는 사이트가 있습니다.** 브라우저로 열면 "삭제된 게시글입니다" 경고 후 뒤로 갑니다. 원본 HTML만 보고 "살아 있는 스팸"이라고 판단하면 안 됩니다.
- **사이트가 스스로 글을 숨기기도 합니다** (`$('#detail_con').remove()`). 원본 HTML에는 스팸 댓글 수백 개가 있지만 화면 DOM에는 없습니다.
- **Mac(16GB)에서 Laya 파인튜닝은 `--micro-batch 16`이면 MPS 메모리가 부족합니다.** `--micro-batch 4 --grad-accum 8`로 줄이거나 코랩 T4에서 학습하세요. 크롤링과 동시에 돌리면 페이지 로딩이 15초를 넘겨 크롤링 결과도 망가집니다.

## 4. 모델 안내 — ⚠️ 저장소에 모델이 없습니다

파인튜닝한 모델(`models/laya-illegal-ad/model.safetensors`)은 **614MB**라서
GitHub의 **파일당 100MB 제한**을 넘어 저장소에 올릴 수 없습니다.
**각자 `pip install laya`로 설치한 뒤** 아래 중 하나로 쓰세요.

### 방법 A. 기본 모델 바로 쓰기 (제로샷, 가장 간단)
`pip install laya`를 하면 처음 실행할 때 HuggingFace에서 기본 모델을 자동으로 받습니다(인터넷 필요, 수백 MB).
```bash
.venv/bin/python -m detector.main http://127.0.0.1:8765/ --out runs/full \
    --model convaiinnovations/laya-multilingual
```

### 방법 B. 직접 파인튜닝해서 만들기
프로토타입과 같은 설정입니다. CPU로도 돌아가지만 시간이 걸립니다.
```bash
# 1) 학습 데이터 생성 (train.jsonl·dev.jsonl, 이미 들어 있으니 수정했을 때만 실행)
#    실행하면 광고/정상별 특징 비율, 규칙 점수 구간 분포, 검증셋·모의 사이트와 겹치는 문장을 출력합니다.
.venv/bin/python training/make_dataset.py

# 2) 파인튜닝 → models/laya-illegal-ad/
#    laya 0.3.28에는 --eval-data 옵션이 없습니다. 평가는 training/eval_classifier.py로 따로 합니다.
#    폴더 이름을 바꾸면 .venv/bin/laya-train 실행 파일이 옛 경로를 가리켜 깨지므로 모듈로 실행합니다.
.venv/bin/python -m laya.train_cli --data training/train.jsonl \
    --base convaiinnovations/laya-multilingual \
    --out models/laya-illegal-ad \
    --epochs 3 --micro-batch 4 --grad-accum 8 --max-len 384 --loss soft-ce --label-smoothing 0.1 --seed 0
```
Mac(16GB)에서는 `--micro-batch 4 --grad-accum 8`이 메모리 안에 들어갑니다(실제 배치 32는 같음). 3에폭에 2\~3시간이 걸리니, 빠르게 하려면 코랩 T4 GPU(무료)에서 `--micro-batch 16 --grad-accum 2 --device cuda`로 학습하세요(약 15분).

`models/laya-illegal-ad`가 있으면 탐지기가 `--model` 옵션 없이 자동으로 씁니다.
다른 모델과 비교하려면 `AD_PURIFIER_MODEL` 환경변수로 모델 폴더를 지정하세요. 화면도 이 모델로 판정하고, 결과 제목에 모델 이름이 표시됩니다.
```bash
AD_PURIFIER_MODEL=$PWD/models/laya-illegal-ad-v3 .venv/bin/python -m ui.server --port 8781
```

## 5. 실행 방법

### 화면으로 실행 (기본)
```bash
.venv/bin/python testsite/server.py     # (테스트할 때) 모의 사이트 → http://127.0.0.1:8765/
.venv/bin/python -m ui.server           # 화면 → 브라우저가 자동으로 열림 (http://127.0.0.1:8780/)
```
Windows에서는 `run_ui.bat`을 실행합니다.

1. URL을 입력하고 **탐지 시작**을 누르면 진행률(수집한 페이지 수, 현재 URL)이 표시됩니다.
2. 끝나면 **대시보드**가 나옵니다.
   - **광고 청정도 게이지:** 청정도 = 100 − 오염 지수입니다. 오염 지수는 아래 네 기준 중 **가장 나쁜 값**을 따릅니다(미세먼지 통합지수와 같은 방식). 페이지 비율만 보면 큰 사이트는 광고가 수백 건이어도 '양호'가 나오기 때문입니다. 게이지 아래에 등급을 정한 기준이 표시됩니다.

     | 기준 | 오염 지수 |
     |---|---|
     | 오염 페이지 비율 | 비율(%) 그대로 |
     | 오염 페이지 수 | 1쪽 10 · 3쪽 30 · 9쪽 50 · 27쪽 70 · 81쪽 90 |
     | 처리할 광고 문구 수 (목록·상세에 중복으로 잡힌 같은 문구는 1건) | 1건 5 · 9건 35 · 27건 50 · 81건 65 · 243건 80 |
     | 숨김형(적격평가 4종) 광고가 남아 있음 | 최소 31 (사이트 변조 신호라 최소 '주의') |

     등급은 청정도 기준으로 청정(100%), 양호(70\~99%), 주의(40\~69%), 오염(0\~39%) 네 단계이고, 색은 10%마다 초록 → 빨강으로 바뀝니다.
   - **통계 카드:** 탐지된 불법광고, 처리 필요, 점검 페이지(소요 시간), 청정 등급
   - **오염원 분석:** 은닉 기법별 건수입니다. 누르면 그 기법만 걸러 볼 수 있습니다.
   - **탐지 로그:** 처리가 필요한 항목부터 보여 주고, 누르면 결과 표의 상세 근거로 이동합니다.
3. 행을 누르면 **판정 근거**를 볼 수 있습니다: 위치(CSS 선택자), 은닉 방식, 원문과 복원 문구, 걸린 키워드, 점수, 규칙/AI 중 무엇이 판정했는지.
4. 항목마다 **검토 상태**(미검토, 불법광고 확인, 오탐, 조치 완료)와 **메모**를 저장하고, 기법·상태·검색어로 걸러 볼 수 있습니다. 조치 완료나 오탐으로 처리하면 청정도가 올라갑니다. **엑셀(CSV) 내보내기**도 됩니다.
5. 왼쪽 **점검 이력**에서 지난 점검 결과를 다시 열 수 있습니다(`history/<실행시각>/`). 카드의 휴지통 버튼으로 하나씩, **전체 삭제**로 한꺼번에 지울 수 있고, 지우기 전에 화면 안에서 한 번 더 확인합니다. 지워지는 것은 `history/` 안의 이력뿐이고, 실행 폴더의 제출용 `result.json`은 그대로 남습니다.
6. **내보내기는 두 가지입니다.**
   - **result.json 다운로드:** 요강 붙임4 형식의 제출용 파일입니다. 탐지 엔진이 저장한 파일을 그대로 내려받습니다.
   - **엑셀(CSV) 내보내기:** 검토·조치 관리용입니다. 앞 6열(`id`, `url`, `is_violation`, `location`, `evidence_text`, `technique`)은 result.json findings와 같은 이름·순서·값이고, 그 뒤에 복원 문구, 판정 근거, 검토 상태, 메모를 붙입니다.

`result.json`과 `report.json`은 요강대로 **구동 폴더**에 생성됩니다. 개발할 때는 프로젝트 루트, exe로 묶으면 exe가 있는 폴더입니다.

**result.json 형식**은 요강 붙임4 스키마를 그대로 따릅니다. 최상위는 `meta`와 `findings`뿐이고, BOM 없는 UTF-8로 저장하며, 0건이어도 `findings: []`를 넣습니다. `eval/validate_result.py`로 검증할 수 있습니다.

**접속 실패 처리**
- 진입 페이지에 접속하지 못하면 화면에 "확인 불가"와 경고가 뜨고, 명령줄 실행은 종료 코드 2로 끝납니다. 0건을 '청정'으로 오판하지 않기 위해서입니다.
- 일부 페이지만 실패하면 그 목록을 경고로 보여 줍니다.
- 실패 정보는 `report.json`의 `entry_failed`, `failed_pages`, `http_errors`에만 기록하고, `result.json` 스키마는 바꾸지 않습니다.

- 화면은 내 PC 안에서만 열리는 로컬 서버(`127.0.0.1`)입니다. 외부 서버에 올리지 않습니다.
- `result.json`은 탐지할 때마다 덮어쓰고, 지난 결과는 `history/`에 남습니다. 이력을 지우려면 `history/` 폴더를 삭제하세요.
- 정상 판정 후보도 보기를 켜면 탐지기가 걸러낸 후보(예: 접근성용 "본문 바로가기")까지 흐리게 표시됩니다.
- "최대 페이지"를 비워 두면 시간 한도(약 19분) 안에서 사이트 전체를 탐색합니다. 실제 사이트를 빠르게 훑어보고 싶을 때만 20 정도로 줄여 보세요.

### 명령줄로 실행

터미널 두 개를 씁니다.

```bash
# 터미널 1 — 모의 사이트 띄우기
.venv/bin/python testsite/server.py            # → http://127.0.0.1:8765/

# 터미널 2 — 탐지 (모델 옵션은 4장 참고)

# 채점 (testsite/ground_truth.json 기준)

# 제출 형식 검증 (요강 붙임4 기준, 브라우저 불필요) — 제출 전 반드시 실행
.venv/bin/python eval/validate_result.py result.json

# 분류기만 비교 (룰 vs Laya, 검증셋 60문장)

.venv/bin/python training/eval_classifier.py models/laya-illegal-ad  # 파인튜닝 모델
```

### 탐지기 옵션
| 옵션 | 기본값 | 설명 |
|---|---|---|
| `<진입URL>` | (필수) | 크롤링을 시작할 주소 |
| `--out` | 구동 폴더 (프로젝트 루트 / exe 폴더) | `result.json`, `report.json` 저장 위치 |
| `--max-pages` | 0 (제한 없음) | 방문할 최대 페이지 수. 0이면 시간 예산 안에서 전부 탐색 |
| `--time-budget` | 1620 (27분) | 전체 목표 시간(초). 적격평가 상한 30분에서 3분 여유 |
| `--llm-reserve` | 360 (6분) | 나중에 붙일 LLM 최종 검증 몫으로 남겨 두는 시간(초). 크롤링은 `time-budget − llm-reserve − 판정 2분`까지 |
| `--concurrency` | 4 | 동시에 여는 탭 수 |
| `--timeout` | 15000 | 페이지 로딩 제한 시간(ms) |
| `--model` | `models/laya-illegal-ad` (`AD_PURIFIER_MODEL` 환경변수로 변경 가능) | Laya 모델 경로 또는 HuggingFace ID |
| `--no-ml` | – | Laya 없이 룰만 사용 |
| `--user-agent` | 일반 Chrome | 크롤러 User-Agent. 기본으로 평범한 한국어 브라우저처럼 접속합니다(로캘 `ko-KR`, `Accept-Language` 포함). 점검 기관에 신원을 밝혀야 하면 뒤에 도구명을 덧붙이세요. |
| `--no-extra` | – | 게시형(은닉 없는) 불법광고 탐지를 끄고 적격평가 4종만 탐지 |
| `--keep-repeats` | – | 여러 페이지에 반복된 같은 광고를 대표 1건으로 합치지 않고 페이지마다 따로 제출 |

> **크롤링 순서와 시간 예산.** 페이지 수로 자르지 않고, 시간 예산 안에서 아래 순서로 **전부** 탐색합니다(`detector/frontier.py`).
> 1. 진입 페이지 주변(메뉴) → 2. 누구나 글을 쓰는 게시판·목록 페이지(Q&A, 자유게시판, 후기 등) → 3. 목록에서 제목이 수상한 글 → 4. 나머지 글·일반 페이지
> - 숨김 광고(적격평가 4종)는 제목이 멀쩡한 글 본문에도 있을 수 있어서, 우선순위만 낮출 뿐 버리지 않습니다.
> - 수상한 제목이 3개 이상 걸린 목록(스팸이 쌓인 게시판)에서 나온 다음 쪽 목록은 크게 앞당깁니다. 목록 한 쪽에 스팸 제목이 20여 개씩 보이기 때문입니다.
> - 같은 글·목록이 여러 주소로 열리는 경우(목록 위치·검색 상태 매개변수, 카페24의 `/board/이름/번호/`와 `list.html?board_no=`)는 한 번만 봅니다.
> - 광고가 있을 수 없는 기능 페이지(글쓰기·수정·삭제·로그인·다운로드 등)는 열지 않습니다. 카페24 글쓰기 페이지는 봇 확인 화면으로 넘어가 시간만 씁니다.
> - 버리는 것은 검색·정렬·달력처럼 같은 형태가 끝없이 생기는 주소뿐입니다(형태당 20개).
> - 게시판 하나가 시간을 독점하지 않도록 게시판끼리 번갈아 봅니다.
> - 시간 한도에 닿으면 새 페이지는 열지 않고 그때까지 찾은 결과로 `result.json`을 저장합니다(`report.json`의 `stopped_by_time`, `left_in_queue`).

> **게시형 불법광고 탐지(추가 유형).** 요강은 "게시·은닉된 불법광고"를 대상으로 하고, 4종(닮은꼴·자모·투명·화면 밖)은 적격평가 기준이며 본심사에서는 추가 유형도 평가합니다.
> 그래서 숨기지 않고 **그대로 게시된** 불법광고(예: 게시판 제목 `✅구글검색 벳모아티비✅ 무료중계`, `비상금대출`)도 탐지합니다(`technique=POSTED`).
> - 적격평가 4종은 `result.json`에 그대로 두고, 게시형은 **`result_extra.json`**(technique=`ETC`, `extra_finding`에 유형명)으로 분리합니다. 적격평가 제출물은 영향받지 않습니다.
> - '보인다'는 것 자체는 단서가 아니므로, 룰 점수가 정상 확정선을 넘는 텍스트만 후보로 올려 오탐·후보 폭증을 막습니다. 공익 안내(`불법 도박 신고 1336` 등)와 실태 보도·채용 안내(`학생`, `의원`, `집계`, `채용` 등)는 감점 규칙으로 제외합니다.
> - **본문 삽입 링크.** 정상 글 문장 사이에 같은 외부 사이트로 가는 링크를 여러 개 끼우고 링크 글자만 `출장마사지`·`홈타이`·`토닥이`로 바꾸는 스팸은, 같은 외부 사이트로 가는 짧은 링크가 3개 이상이고 그중 하나라도 광고 키워드면 그 링크 전부에 가산점(`link-farm:호스트`)을 줍니다.
> - **숫자 위장 복원.** `l9금`, `O6O-5OO-266O`, `ㅇIㅇ-5309`처럼 숫자 자리에 닮은 글자를 쓴 표기는 판정할 때 숫자로 되돌려 보고, 위장 흔적 자체도 가산점(`digit-obfuscation`)을 줍니다.

> **중복 탐지 합치기.** 같은 페이지에서 내용이 같고 위치가 같은 줄(한쪽이 다른 쪽을 감싸거나 같은 부모 아래 형제)이면 한 건만 남깁니다. 숨김 블록 안의 요소가 게시형으로 또 잡힌 경우도 숨김 블록 한 건으로 봅니다.
> 남기는 순서는 은닉 기법 > 게시형, 바깥 요소 > 안쪽 요소입니다. 단, 같은 요소에 서로 다른 은닉 기법이 함께 잡히면 채점이 기법까지 보므로 둘 다 남깁니다. 합친 항목은 `report.json`의 `duplicates`에 어디로 합쳤는지와 함께 남습니다.
>
> **여러 페이지 반복 합치기.** 같은 문구·같은 기법·같은 자리(목록의 몇 번째 줄인지는 무시)가 여러 페이지에 나오면 — 모든 글 아래에 붙는 게시판 목록, 공통 하단, 같은 글의 다른 주소 — 대표 1건(주소가 가장 짧은 페이지)만 `result.json`·`result_extra.json`에 냅니다. 나머지 페이지는 대표 항목의 `also_on`에 남고, 화면에 "외 N개 페이지"로 보입니다. 정확도 점수(정답 ÷ 제출)를 지키기 위한 것으로, 정답 목록이 반복 페이지마다 있다면 `--keep-repeats`로 끌 수 있습니다(회의 안건).

> **점검 범위는 진입 사이트뿐입니다.** 링크 주소뿐 아니라 이동(리다이렉트)이 끝난 **최종 주소**도 같은 사이트인지 확인합니다(`www` 유무는 같은 사이트로 봅니다).
> 게시판의 `link.php` 같은 외부 링크 중계 주소가 다른 사이트로 넘어가면 그 페이지는 점검·결과에서 빼고 `report.json`의 `external_skipped`에 기록합니다.
> 시작 주소 자체가 다른 주소(예: `www`)로 넘어가면 그 도착지를 점검 범위로 삼습니다.
> 링크로 연결되지 않은 페이지(고아 페이지)는 크롤링으로 찾을 수 없습니다.

> **접속이 막히는 사이트에 대하여.** 끝 슬래시가 없어 내부 주소로 잘못 리다이렉트되는 경우(`/path` → 접속 불가)는 자동으로 `/path/`를 다시 시도합니다.
> 반면 일부 공공 사이트(예: 정부24)는 자동 접속 자체를 차단합니다(스크립트 기반 단말 차단). 이때는 User-Agent를 바꿔도 뚫리지 않으며, 이는 기관이 의도한 접근 통제이므로 우회하지 않습니다.
> 실제 기관 사이트를 점검하려면 해당 기관에 점검 IP·User-Agent 허용을 요청하는 것이 정상 절차입니다.
